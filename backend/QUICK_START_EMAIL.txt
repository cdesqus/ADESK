================================================================================
HOW IT WORKS
================================================================================

1. EMAIL ARRIVES at helpdesk@idesolusi.co.id

2. BACKGROUND JOB (every 5 minutes):
   - Connects to IMAP server
   - Fetches all unread emails
   - For each email:
     a. Parse email (headers, body, attachments metadata)
     b. Extract sender's domain (admin@mitsubishi.com → mitsubishi.com)
     c. Find matching customer by domain
     d. Create ticket with matched customer_id
     e. Send auto-reply email to sender
     f. Mark email as read
     g. Log processing result

3. CUSTOMER RECEIVES AUTO-REPLY:
   - From: helpdesk@idesolusi.co.id
   - Subject: Re: [original subject]
   - Body: Includes ticket ID (TK-123) and response time expectation

4. ADMIN SEES TICKET:
   - New ticket in dashboard
   - Source: EMAIL
   - Customer: Auto-matched by domain
   - Email tracking via email_logs table

================================================================================
DOMAIN MATCHING LOGIC
================================================================================

The system matches email domains in this order:

1. EXACT MATCH (case-insensitive)
   Email from: admin@mitsubishi.com
   Customer domain: mitsubishi.com
   Result: MATCH

2. SUBDOMAIN MATCH
   Email from: support@asia.toyota.co.id
   Customer domain: toyota.co.id
   Result: MATCH (subdomain recognized)

3. BASE DOMAIN MATCH
   Email from: info@siemens.de
   Customer domain: siemens.com
   Result: MATCH (same base domain, different TLD)

4. NO MATCH
   Email from: unknown@example.com
   Result: Creates ticket under "Unknown Customer"
   (If "Unknown Customer" customer doesn't exist, creates it)

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE: "Email poller not starting"
SOLUTION:
  1. Check .env has EMAIL_USER and EMAIL_PASSWORD
  2. Verify database is running
  3. Run: go mod tidy
  4. Check application logs for error messages

ISSUE: "Failed to connect IMAP"
SOLUTION:
  1. Verify email/password correct
  2. Test IMAP connection: telnet imap.gmail.com 993
  3. For Gmail, use app password (not regular password)
  4. Check firewall isn't blocking port 993

ISSUE: "Ticket created but wrong customer"
SOLUTION:
  1. Check customer.domain field is set: SELECT domain FROM customers;
  2. Check email_logs for domain_matched value
  3. Verify domain format (should be "mitsubishi.com" not "www.mitsubishi.com")

ISSUE: "Auto-reply not sent"
SOLUTION:
  1. Check SMTP credentials are correct
  2. Verify SMTP server connectivity: telnet smtp.gmail.com 587
  3. Check logs for "Failed to send email" messages
  4. Verify database has email_logs table

ISSUE: "Email created with 'Unknown Customer'"
SOLUTION:
  1. Check which domains are creating unknowns:
     SELECT domain_matched, COUNT(*) FROM email_logs
     WHERE status = 'UNKNOWN_DOMAIN' GROUP BY domain_matched;
  2. Add these domains to existing customers or create new customers

================================================================================
MONITORING
================================================================================

View real-time email logs:
  SELECT created_at, sender_email, domain_matched, status FROM email_logs
  WHERE created_at > NOW() - INTERVAL '1 hour'
  ORDER BY created_at DESC;

Count by status:
  SELECT status, COUNT(*) as count FROM email_logs
  GROUP BY status;

Find failing senders:
  SELECT sender_email, COUNT(*) as failures FROM email_logs
  WHERE status = 'FAILED'
  GROUP BY sender_email;

Check tickets from email:
  SELECT t.id, t.title, t.customer_id, el.sender_email, t.created_at
  FROM tickets t
  LEFT JOIN email_logs el ON el.ticket_id = t.id
  WHERE t.source = 'EMAIL'
  ORDER BY t.created_at DESC;
