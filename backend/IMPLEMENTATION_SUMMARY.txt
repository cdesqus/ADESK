IMPLEMENTED FEATURES - PHASE 2
================================================================================

1. IMAP EMAIL SERVICE (internal/email/imap.go)
   - TLS connection to IMAP server
   - Fetch unread emails from INBOX
   - Mark emails as read after processing
   - Automatic reconnection on failure
   - Full error handling

2. EMAIL PARSER (internal/email/parser.go)
   - Parse IMAP messages to structured format
   - Extract headers (From, To, Subject, Date, Message-ID)
   - Multipart MIME email support
   - Text and HTML body extraction
   - Attachment metadata extraction (no file storage)
   - HTML stripping for clean text
   - Email validation

3. DOMAIN MATCHER (internal/email/matcher.go)
   - Extract domain from sender email
   - Exact domain matching (case-insensitive)
   - Subdomain matching (admin@sub.domain.com → domain.com)
   - Base domain matching (different TLDs)
   - Support for various domain formats
   - Unknown domain fallback

4. AUTO-CREATE TICKET HANDLER (internal/handlers/email.go)
   - POST /api/email/webhook endpoint
   - Parse email data
   - Match sender domain to customer
   - Create ticket with matched customer_id
   - Log all processing attempts
   - Send auto-reply emails

5. AUTO-REPLY SERVICE (internal/email/sender.go)
   - SMTP email sending with TLS
   - Auto-reply template generation
   - Include ticket ID in reply
   - Formatted HTML/text emails
   - Non-blocking error handling

6. BACKGROUND EMAIL POLLER (internal/jobs/email_poller.go)
   - Goroutine-based polling
   - Configurable interval (default 5 minutes)
   - Automatic reconnection
   - Graceful shutdown support
   - Detailed logging of all actions
   - Continues on individual email failure

7. EMAIL LOGGING (EmailLog model)
   - Track all email processing
   - Status: SUCCESS, FAILED, UNKNOWN_DOMAIN
   - Store error messages
   - Link to customer and ticket
   - Timestamps for auditing

4. API ENDPOINTS (Complete CRUD)

   CUSTOMERS:

   - DELETE /api/tickets/:id            - Soft delete

DATABASE SCHEMA
================================================================================

USERS table:
- id (PK)
- email (unique)
- password (hashed)
- role (ADMIN, SUPPORT, ENGINEER, VIEWER)
- created_at, updated_at, deleted_at

CUSTOMERS table:
- id (PK)
- name
- domain (unique)
- email_support
- is_active
- created_at, updated_at, deleted_at

ENGINEERS table:
- id (PK)
- customer_id (FK)
- name
- email
- whatsapp_number
- skills (JSONB array)
- is_active
- created_at, updated_at, deleted_at

TICKETS table:
- id (PK)
- customer_id (FK)
- engineer_id (FK, nullable)
- title
- description
- status (OPEN, IN_PROGRESS, RESOLVED, CLOSED)
- priority (LOW, MEDIUM, HIGH, URGENT)
- category
- source (EMAIL, CHAT, PHONE, WEB)
- email_from
- created_at, updated_at, resolved_at, deleted_at

UPDATES table:
- id (PK)
- ticket_id (FK)
- engineer_id (FK, nullable)
- message
- action_type (COMMENT, STATUS_CHANGE, ASSIGNED, REOPENED)
- created_at, updated_at, deleted_at
